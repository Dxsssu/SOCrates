# AIT-ADS Data

The datasets are not distributed with this repository. This document explains
which files are needed, where to download them, and how to arrange them for the
SOCRates reference implementation.

## Data sources

### Required: AIT Alert Data Set (AIT-ADS)

Download AIT-ADS version 1 from the official Zenodo record:

- Dataset page: <https://doi.org/10.5281/zenodo.8263181>
- Alert archive: <https://zenodo.org/records/8263181/files/ait_ads.zip?download=1>
- Attack-phase intervals: <https://zenodo.org/records/8263181/files/labels.csv?download=1>

AIT-ADS contains 2,655,821 synthetic alerts from eight enterprise scenarios.
For every scenario, the archive provides one AMiner file and one combined
Wazuh/Suricata file. The files use JSON Lines (JSONL/NDJSON): each line is one
complete JSON object even though the filename extension is `.json`.

### Required for the paper evaluation: per-alert labels

The `labels.csv` file from Zenodo contains attack-phase time intervals. It does
not provide a reliable malicious/benign label for every individual alert. The
SOCRates evaluation runner therefore uses the per-alert label archive published
in the official AIT-ADS companion repository:

- Companion repository: <https://github.com/ait-aecid/alert-data-set>
- Label archive: <https://raw.githubusercontent.com/ait-aecid/alert-data-set/main/alerts_csv/alerts_csv.zip>

The archive contains one `<scenario>_alerts.txt` file for each scenario. These
files preserve the official row order and include both `time_label` and
fine-grained `event_label` columns.

### Optional: source logs and netflows

The following datasets are needed only to regenerate or change the official
event-level labeling procedure. They are not needed when using the published
AIT-ADS alerts and `alerts_csv.zip`:

- AIT Log Data Set V2.0 (AIT-LDSv2):
  <https://doi.org/10.5281/zenodo.5789064>
- AIT Netflow Data Set (AIT-NDS):
  <https://doi.org/10.5281/zenodo.6610489>

AIT-LDSv2 is much larger than AIT-ADS because it includes host logs, labels,
configuration information, and packet captures. Do not download it unless the
raw evidence or label-generation workflow is required.

## Recommended directory layout

Arrange the downloaded and generated files as follows:

```text
SOCrates/
├── data/
│   ├── README.md
│   ├── ait_ads/                    # downloaded AIT-ADS files
│   │   ├── ait_ads.zip             # optional after successful extraction
│   │   ├── labels.csv
│   │   ├── fox_aminer.json
│   │   ├── fox_wazuh.json
│   │   ├── harrison_aminer.json
│   │   ├── harrison_wazuh.json
│   │   ├── russellmitchell_aminer.json
│   │   ├── russellmitchell_wazuh.json
│   │   ├── santos_aminer.json
│   │   ├── santos_wazuh.json
│   │   ├── shaw_aminer.json
│   │   ├── shaw_wazuh.json
│   │   ├── wardbeck_aminer.json
│   │   ├── wardbeck_wazuh.json
│   │   ├── wheeler_aminer.json
│   │   ├── wheeler_wazuh.json
│   │   ├── wilson_aminer.json
│   │   └── wilson_wazuh.json
│   ├── labels/
│   │   └── alerts_csv.zip          # official per-alert label archive
│   └── labeled/                    # generated by the preparation command
│       ├── labeling_summary.json
│       ├── fox_aminer.json
│       ├── fox_wazuh.json
│       └── ...
└── src/
```

The raw and generated dataset files are large and should normally remain
untracked. Do not commit them to Git unless the repository explicitly uses an
appropriate large-file storage policy.

## Download and extract

Run the following commands from the repository root:

```bash
mkdir -p data/ait_ads data/labels data/labeled

curl -L \
  'https://zenodo.org/records/8263181/files/ait_ads.zip?download=1' \
  -o data/ait_ads/ait_ads.zip

curl -L \
  'https://zenodo.org/records/8263181/files/labels.csv?download=1' \
  -o data/ait_ads/labels.csv

curl -L \
  'https://raw.githubusercontent.com/ait-aecid/alert-data-set/main/alerts_csv/alerts_csv.zip' \
  -o data/labels/alerts_csv.zip

unzip data/ait_ads/ait_ads.zip -d data/ait_ads
```

If direct access to the GitHub label archive is unavailable, clone the official
companion repository and copy the archive:

```bash
git clone --depth 1 https://github.com/ait-aecid/alert-data-set.git /tmp/alert-data-set
cp /tmp/alert-data-set/alerts_csv/alerts_csv.zip data/labels/alerts_csv.zip
```

## Verify the AIT-ADS download

The Zenodo record publishes the following MD5 checksums:

```text
43db6b1f0996e0024befd617706c50e9  ait_ads.zip
60ff33796c77fd2136c4d1a4bc841bd9  labels.csv
```

Verify them from the repository root:

```bash
md5sum data/ait_ads/ait_ads.zip data/ait_ads/labels.csv
```

Also confirm that the archive contains exactly 16 alert files:

```bash
find data/ait_ads -maxdepth 1 -type f \
  \( -name '*_aminer.json' -o -name '*_wazuh.json' \) | sort
```

## Generate the labeled evaluation files

The published AIT-ADS JSON files do not contain the per-alert `label` field
required by the SOCRates experiment runner. From the repository root, merge the
official labels into a separate output directory:

```bash
python -m src.data.ait_ads_labeling \
  --input-dir data/ait_ads \
  --label-archive data/labels/alerts_csv.zip \
  --output-dir data/labeled \
  --scenarios fox harrison russellmitchell santos shaw wardbeck wheeler wilson \
  --workers 2
```

The command validates row alignment before writing final files. It assigns:

- `benign` to alerts outside annotated attack windows;
- `false_positive` to alerts inside an attack window without an event match;
- the concrete event name, such as `dns_scan` or `webshell_cmd`, to matched
  attack alerts.

The raw files under `data/ait_ads/` remain unchanged. Configure SOCRates to read
the generated files under `data/labeled/`, for example:

```yaml
ait_ads:
  input_paths:
    - data/labeled/fox_wazuh.json
    - data/labeled/fox_aminer.json
  output_directory: results/fox
  hat_initialization_fraction: 0.20
  outside_attack_window_label: benign
```

To prepare only one scenario for a quick check, replace the scenario list with
`--scenarios fox`.
